# MiniMax TP8 满 B32 固定工作量对照

MiniMax-M3.1-Flash 在八张 A100 上使用 SGLang CUDA Graph、BF16 KV 和共同的 `mem_fraction_static=0.84`。两臂由 SGLang 自动定容。固定臂将训练数据上冻结的 40 层卸载到主机，其余 20 层直读驻留 KV，跨层共享池关闭。对照是原生全层 HiSparse。

同一封存 cohort 共 32 条真实输入，长度 16–32 Ki token。测量批次每条生成 512 token 并统一启用 `ignore_eos`，暖机保持原配置。计时窗跳过首个满批屏障后的 32 步，要求实报 CUDA Graph 并且至少有 128 个连续的满 B32 步。

| 指标 | 原生全层 HiSparse | 固定卸载 40 层 | 变化 |
| --- | ---: | ---: | ---: |
| 满 B32 稳态吞吐 | 408.35 token/s | 543.87 token/s | **+33.19%** |
| 稳态 TPOT p50 | 78.13 ms | 58.64 ms | **−24.94%** |
| 稳态 TPOT p95 | 78.14 ms | 58.66 ms | **−24.93%** |
| TTFT p50 | 42.10 s | 42.18 s | +0.19% |
| 暖机后连续满批步 | 476 | 476 | 各有 60 个窗内 Graph 调度样本 |
| 完成请求 | 32/32 | 32/32 | 每条生成 512 token |
| 批后八卡 NVML 范围 | 72,738–73,314 MiB | 72,632–73,208 MiB | 范围整体低 106 MiB |

两个原生测窗分别为 408.74 和 408.35 token/s，相差 0.096%。峰值显存、自然 EOS 和正式 PR 验收使用各自的独立测量。该表只是一组受控工作量对照。它支持固定逐层卸载在这个压力点降低稳态解码成本；自然请求的跨 cohort 结论仍待复验。原生和固定臂的逻辑 KV 容量分别为 1,037,824 与 889,344 行，均满足这批请求的 858,112 行预留。0.7828 的旧共同预算下固定臂未通过 B32 准入。
