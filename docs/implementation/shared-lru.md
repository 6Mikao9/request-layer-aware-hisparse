**Assignment for the coding agent.** Open one implementation PR against this repository. The maintainer runs target-hardware tests after review. ## Result the PR must expose

For the MiniMax-M3.1-Flash host-backed sparse main KV, a layer may evict a historical row owned by another layer of **the same live request on the same TP rank** and use the freed K/V address. Every layer executes the model's original indexer and attention. Keep ordering, duplicates, valid lengths, tail behavior and padding exactly as in the pinned backend. Equal logical token IDs at two physical KV layers identify different payloads. Shared selection indices give no permission to reuse payloads. Full history remains retrievable. This issue runs all eligible layers through HiSparse. Issue 3 can later pass a smaller set of eligible physical layers. Derive the set from model/pool mappings; do not bake 60 into indexing.

Implement a slow transparent device algorithm before optimizing. A CPU simulator, changing only active widths in equal-size K/V planes, pooling LRU counters, or reusing an unverified pointer across two layer bases cannot satisfy the physical sharing requirement. The clean native control should run through its original gather/attention kernels.

## Public configuration

In this issue the placement is `placement.mode=native`; it retains normal native HiSparse staging/admission. `hot_pool.mode=shared` is the explicit opt-in for sharing among host-backed layers. `hot_pool.scope=request_rank` is the only supported shared domain here. No file or an all-default file selects native behavior and allocates zero experimental GPU state. The following proposed subordinate controls are part of this issue. Integrate them into the common parser; reject misspellings and inconsistent combinations, and emit resolved configuration and effective capabilities in a startup receipt.

| Field | Values or default | Meaning |
|---|---|---|
| `hot_pool.mode` | `isolated` (default), `shared` | Isolated constrains ownership to a layer. Shared permits cross-layer transfer. |
| `hot_pool.layout` | `native` (default), `arena` | Arena+isolated uses the candidate address and gather path with borrowing disabled. Shared requires arena. |
| `hot_pool.eviction` | `lru` (default), `fifo` | Within the allowed domain use last-access epoch or admission epoch respectively. A hit refreshes only LRU. |
| `hot_pool.admission` | `all` (default), `bypass_list` | Bypass sends exact selections of explicitly listed weak-reuse layers through charged scratch and retains no new rows there. Publish/validate physical IDs in `hot_pool.bypass_layers`; freeze list from training only. |
| `hot_pool.quota` | `none` (default), `static`, `soft_floor` | Static partitions use `hot_pool.quota_rows` keyed by absolute layer ID and enforce the total. For soft floors, prefer victims above floor, then the oldest safe eligible victim if none is above. Publish floor breaches and never override live pins. |
| `diagnostics.mode` | `none` (default), `counters`, `nsys` | Diagnostics emit metadata only in dedicated runs. Clean serving uses none. |

For each optimization in the PR specify its reference alternative, add a configuration parity test and emit its actual resolved value. Do not add inert flags. If a fairness, bypass, or optimization choice requires extra scratch, include it in the budget and paired control. Never silently switch to uniform/eager on rejection or memory pressure.

## Implementation sequence and observable interfaces

1. **Model a request lifetime and an atomic access batch.** Add a pure CPU reference with operations equivalent to `admit(slot, generation, rank, eligible_layers, initial_rows, capacity)`, `resolve(batch, epoch)`, `complete(lease)` and `finish(request)`. A batch carries ordered selector blocks, actual sequence length, physical layer and real/padded status. Return physical row IDs in original selection order, per-row classification (history hit, history miss, latest, padding), unique history counters and a lease for protected rows. Duplicates point at the same valid bytes and do not double-count transfer. Derive padding/invalid block behavior from the pinned kernel. Define deterministic ties: free slots first, otherwise minimum eligible (policy timestamp, physical slot ID). All entries touched during one layer invocation share one epoch. Epochs increase in actual per-request layer execution order. Use a wrap-safe counter. Distinct requests in the same GPU batch cannot evict one another. Keep TP rank state local even when a KV head is replicated.
2. **Implement backing storage.** Allocate aligned K/V planes with stable addresses and fixed-size device tables *before* capture. Resolve (request-generation, physical KV layer, logical token) to a rank-local 32-bit-or-wider arena row; store reverse key, state, recency, physical owner and request generation. Verify address multiplication/offset bounds with 64-bit arithmetic. Native local LRU short indices cannot hold 60×4096=245,760 slots. A page allocator may reserve spans per request, with rows within them reusable across layers. If ownership transfers only in whole pages, prevent one live row from being overwritten with the rest of the page and label that variant page-granular; the exact row-LRU reference must remain available for comparison. Do not allocate a second full native hot cache for the same long-lived rows. If prefill uses the native full planes, partition/account the two uses and their transient overlap or reuse their backing before claiming equality.
3. **Implement resolve, fetch, consume.** Snapshot hits for the *complete* layer selection, lock every currently selected hit before choosing any victims, coalesce duplicate misses, reserve destinations and invalidate old forward+reverse mappings as one ownership change. Gather K and V from that request's host-backed original logical positions. Publish a tag only after both payloads have arrived. Fill the output in native order. Partition latest-row and scratch handling explicitly: either place tails/scratch at stable offsets accessible to the same consumer, or resolve through an adapter that selects compatible bases without changing attention semantics. It must handle mixtures of history, latest and short requests in one batch. Cache hits must not trigger K/V host copies; bypass must still provide every selected row. Validate from the consumer's actual address and bytes independently of the policy map.
4. **Handle synchronization, retries and capture.** Maintain distinct free/reserved/loading/valid/in-use states or equivalent leases. Charge a page only once; retain a pin until its last attention reader and prefetch reader complete. For single-stream decode, order GPU operations on the same stream. For overlapping streams, perform device event waits before publication, overwrite and release. A copied row is not reusable just because the copy finished. A tail may be overwritten only after previous-token backup has completed or a valid alternate copy exists. Refuse unsafe eviction when all candidates are pinned. Pre-size scratch/reservations for maximum admitted in-flight work or establish a schedulable serial ordering before capture; avoid GPU busy-waits that can deadlock within a graph. Abort partial reservation without losing valid old payloads, or fail that request cleanly and retire its generation only after completion fences. Validate stale callbacks, delayed copies and allocator OOM. On repeated finish do not double-free. Admission decisions that affect batch shape must agree across TP ranks or roll back before admitting on any rank. Cache victims can differ by rank.
5. **Bind the normal graph path.** Set up fixed-capacity request IDs, generations, real-row count, lengths, selector inputs, resolved slots, leases and diagnostic buffers. No host decision per layer, CPU sync, tensor-to-list/CPU transfer, dynamic allocation, host polling, per-layer cross-rank collective or capture-time shape change in the shared decode path. Preserve native fast paths only where their storage invariants still hold (a short row uses the direct path only while all referenced rows are guaranteed valid). Graph replay must support different real rows in the same bucket; padded rows must not mutate state. Keep release/slow-path admission outside capture or implement safe captured device transitions. Add an explicit compatibility check for unsupported platform, schema, speculative decoding or layout. Keep native shared-index prefetch on eligible models as a separately verified control; never prefetch a future MiniMax selection that is unavailable.
6. **Provide a CPU replay/validation entry point.** Add `python -m unittest discover -s tests -p "test_shared_lru*.py"` or an equally explicit one-command replacement in the PR. Add a CPU-only CLI with syntax equivalent to `python -m <your_package>.shared_lru_replay --fixture <tracked_fixture> --config <tracked_arm.json> --output <result.json>`. Replace all placeholders with actual repo-relative paths in the submitted README/PR; include exact commands for stock, isolated arena and shared arena. Make the fixture deterministic, seeded, small, free of prompts/weights; synthesize host K/V bytes independently from (generation, rank, layer, token, plane, element). Implement a second direct reader to check every resolved row, offset and validity bit. An adapter dry-run must resolve the pinned symbols/config without model download and show the selected implementation, expected tensor contracts and budget units. A fake allocator must distinguish *physical span allocated* from *logical occupancy*. Document GPU tests in separate, opt-in entry points.

## Equal-byte contract

Use the capacity selected by the stock runtime and the owner-provided memory fraction. `H=4096` denotes saturated historical hot rows per request and eligible physical layer in the native comparison; it is not a total token or context limit. `K=2048` is the MiniMax model's flattened maximum selection width in this experiment (16×128). On 8×A100-SXM4-80GB TP8, MXFP8-weight compatibility path with BF16 projections as required on SM80 and BF16 main KV, one rank-local historical row with one local KV head contains K and V each 128×2 B = 512 B combined. Confirm actual tensor geometry/dtype at startup. For 60 saturated layers, history payload is 120 MiB/request/rank; a 128-row latest page per layer adds 3.75 MiB. Short requests may own fewer pages. Preserve original latest-token treatment and pinned host history. TP4 should be selectable later by inspecting actual rank/head geometry and pool capacities. Avoid hardcoded B, TP group membership, total token limit, or artificial context truncation.

Per arm and rank emit peak committed/allocated bytes for shared/native main KV, live history rows, tails, in-flight scratch and prefetch, indexes, allocator metadata (including reverse tags/LRU), request tables, weights, Graph workspace, alignment, fragmentation, and prefill overlap. Also record whole-device peak and pinned host bytes separately. Classify estimated/unavailable fields, use mutually exclusive categories or explicitly list overlaps. Aggregate constraints by tightest rank. Avoid summing maxima from different times to imply a measured peak. At a fixed total HBM limit, charge extra metadata against candidate hot capacity. If native H and new arena cannot provide equal budget *and* the same feasible batch, report that point as infeasible; do not grant more memory. Log row and byte budgets, real occupancy, real free/leaseable pages, and actual concurrency independently.
